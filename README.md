# autodesk-fusion-api

A Claude skill for writing, debugging, and explaining Autodesk Fusion (Fusion 360) Python scripts and add-ins — covering `adsk.core`, `adsk.fusion`, `adsk.cam`, `adsk.drawing`, `adsk.electron`, `adsk.sim`, and `adsk.volume`.

Fusion's Python API has roughly 1,750 classes across those seven modules, and method signatures, enum values, and argument order are easy to misremember or hallucinate. This skill bundles Autodesk's own auto-generated API stub files as ground truth, plus reference docs on scripting patterns, common modeling workflows, and which module covers what — so Claude looks things up instead of guessing.

## What's in here

The skill files live directly at the repo root — there's no wrapping subfolder — alongside the usual repo scaffolding:

```
.
├── SKILL.md                        # entry point: when to use this, how to look things up
├── references/
│   ├── api-stubs/                  # Autodesk's official API stub files (see below)
│   │   ├── __init__.py
│   │   ├── core.py
│   │   ├── fusion.py
│   │   ├── cam.py
│   │   ├── drawing.py
│   │   ├── electron.py
│   │   ├── sim.py
│   │   └── volume.py
│   ├── index-*.md                  # per-module class table of contents
│   ├── module-map.md               # what each of the 7 modules covers, and which to use for a task
│   ├── scripting-patterns.md       # script vs. add-in vs. command boilerplate, event handler gotchas, error handling, units
│   └── workflows.md                # verified worked examples (sketch→extrude, parameters, timeline, export, etc.)
├── .github/workflows/release.yml   # auto-tags and packages a .skill release on every merge to main
├── README.md
├── LICENSE
└── .gitignore
```

This matters for installing: wherever these instructions say "the repo root," that's `SKILL.md` and `references/` directly — not a subfolder named after the skill.

## About the API stub files

The files under `references/api-stubs/` are **Autodesk's own auto-generated Python API stubs** — the same files Fusion ships for code-intellisense in editors like VS Code, generated directly from the current Fusion API rather than hand-written documentation. They are not something the author of this repo wrote; they're included here as reference/ground-truth data so Claude can look up exact class and method signatures instead of relying on memory.

They were copied as-is from a local Fusion install:

```
%USERPROFILE%\AppData\Roaming\Autodesk\Autodesk Fusion 360\API\Python\defs\adsk
```

captured from **Fusion version `2704.1.53`**. If your Fusion install is a different version, the API surface may differ — see "Updating the stubs" below.

A few things worth knowing:
- These stubs are Autodesk's intellectual property. They're bundled here for reference purposes; if you plan to redistribute this repo widely (rather than using it personally or internally), check Autodesk's terms for their API/SDK materials before doing so. This repo doesn't make any claim about what license they fall under.
- They reflect a specific snapshot of the Fusion API and will drift out of date as Autodesk ships new releases. If you hit a class/method that doesn't match what's in your Fusion install, that's the most likely reason — consider regenerating the stubs from your own Fusion installation (they ship alongside the app) and swapping them in.
- The stubs are stub-only: signatures and docstrings, no real implementation (`# This file is automatically generated for code intellisense only. It does not reflect the actual implementation.` is the header on each file). They're excellent for looking up exact signatures, argument order, and enum values, but they can't be executed to test against.

## Installing

**Claude.ai** — download the latest `autodesk-fusion-api.skill` from the [Releases page](https://github.com/cartagena/fusion-skill/releases) and use the "Save skill" option when it's shared/uploaded in a chat. Requires skill creation to be enabled for your organization.

**Claude Code / Cowork — clone the repo:**
```bash
git clone https://github.com/cartagena/fusion-skill.git ~/.claude/skills/autodesk-fusion-api
```
Use `~/.claude/skills/` for a skill available in every project, or `.claude/skills/` inside a specific project to scope it there. Claude picks up any folder with a `SKILL.md` at its root automatically.

**Claude Code / Cowork — from a release instead of git:**
```bash
curl -L -o autodesk-fusion-api.skill https://github.com/cartagena/fusion-skill/releases/latest/download/autodesk-fusion-api.skill
mkdir -p ~/.claude/skills
unzip autodesk-fusion-api.skill -d ~/.claude/skills/
```
The `.skill` file already contains a top-level `autodesk-fusion-api/` folder, so extract it *into* `~/.claude/skills/` (not `~/.claude/skills/autodesk-fusion-api/`) — otherwise you'll end up with an extra nested `autodesk-fusion-api/autodesk-fusion-api/` and Claude won't find `SKILL.md`.

**Packaging as a `.skill` file yourself** (e.g. after making local changes, without waiting for a release):
```bash
staging="/tmp/autodesk-fusion-api"
mkdir -p "$staging"
cp -r SKILL.md references "$staging/"
( cd /tmp && zip -r ~/autodesk-fusion-api.skill autodesk-fusion-api )
```
This only bundles `SKILL.md` and `references/` — not `README.md`, `LICENSE`, `.gitignore`, or `.github/` — matching what the release workflow below produces. In most cases you won't need to do this by hand: every merge to `main` triggers `.github/workflows/release.yml`, which tags a new version and attaches a freshly packaged `.skill` file to a GitHub Release automatically.

## Updating the stubs

If you want to refresh `references/api-stubs/` from a newer Fusion release, copy the `.py` files from the same location on your machine —
```
%USERPROFILE%\AppData\Roaming\Autodesk\Autodesk Fusion 360\API\Python\defs\adsk
```
— over the existing ones, note the new Fusion version in this README, and regenerate the index files (a short script that greps `^class ` definitions and their first docstring line per file — see `references/index-*.md` for the expected format).
